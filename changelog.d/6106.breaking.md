Symbolic models saved with `BaseModel.to_json`, `BaseModel.to_config` or `Serialise.save_custom_model` are now written as a table of unique expressions (schema version `2.0`): each expression is stored once and referenced by index, instead of being nested in full at every use. Files are 8x to 126x smaller (a DFN with degradation goes from 19.9 MB to 158 kB) and save and load up to 45x faster. Files written by older versions still load; to upgrade one, load it and save it again with `pybamm.BaseModel.from_json(old_file).to_json(new_file)`. Code that reads the JSON directly must follow `{"$ref": index}` entries into the top-level `nodes` table, and older PyBaMM versions cannot read the new files.
